# 레시피 예제 파일 관리

- 다운로드 목록: `/astra/recipe/`
- 개별 레시피: `/astra/recipe/04/` (각 디렉터리에 실제 `index.html`이 있습니다.)
- 페이지 간 링크는 `index.html`까지 명시하므로, 서버에서 접속할 때뿐 아니라 로컬의 `astra/index.html` 파일을 더블클릭해서 열어도 폴더 색인 대신 해당 페이지로 이동합니다.
- 레시피 04의 자료는 `recipe/04/`, 레시피 05의 자료는 `recipe/05/`, 레시피 14의 사원명부는 `recipe/14/`에 있습니다.

## 파일 추가

1. `recipe/04/`, `recipe/05/`처럼 해당 번호 폴더에 예제 파일을 넣습니다. 폴더 안에 하위 폴더를 두어도 됩니다.
2. 파일이 있는 레시피만 자동으로 목록에 등록됩니다. 제목을 표시하려면 `recipe/catalog.json`의 `titles`에 번호와 제목을 적습니다. 제목만 등록해 두어도 예제 파일이 없으면 페이지나 빈 폴더를 만들지 않습니다.
3. 로컬 확인 시 저장소 루트에서 `python scripts/build_recipes.py`를 실행합니다.
4. 파일을 GitHub `main` 브랜치에 올리면 `.github/workflows/pages.yml`이 목록과 ZIP을 다시 만들고 사이트를 배포합니다.

GitHub 저장소의 **Settings → Pages → Build and deployment → Source**는 **GitHub Actions**로 설정해야 합니다.

레시피 개수와 마지막 번호는 고정하지 않습니다. 번호 폴더에 예제 파일을 넣으면 다음 생성 시 해당 번호의 페이지가 생깁니다. `04`, `17`, `105`처럼 번호가 떨어져 있어도 중간 번호를 자동으로 채우지 않습니다. 이전·다음 링크도 실제 등록된 레시피만 연결합니다. `recipe 04`, `recipe_04` 같은 기존 폴더명도 인식합니다.

예제 파일을 모두 제거하면 해당 레시피가 목록에서 빠지고, 자동 생성된 페이지와 ZIP도 정리됩니다. 직접 작성한 페이지나 예제 파일은 지우지 않습니다. 레시피를 삭제하거나 번호를 바꿀 때에는 책에 적힌 기존 주소도 함께 확인하세요.

## 생성 파일

- `recipe/index.html`과 번호 폴더의 `index.html`: 자동 생성됩니다. 제목은 `catalog.json`, 레이아웃은 `scripts/build_recipes.py`에서 수정하세요.
- `recipe/_downloads/`: 레시피별 ZIP이 자동 생성됩니다.
- `recipe/assets/`: 공통 디자인과 검색 기능입니다.
- 예제는 번호 폴더 안에만 넣으세요. 숨김 파일, Office 임시 파일, 각 번호 폴더의 최상위 `index.html`은 다운로드 목록에서 제외됩니다. HTML 예제의 이름은 `example.html`처럼 지정하거나 하위 폴더에 넣으세요.
- 파일이 없는 레시피는 다운로드 목록에 표시하지 않고, 빈 폴더나 개별 페이지도 미리 만들지 않습니다.

정적 페이지이므로 GitHub API, 로그인, 별도 데이터베이스가 필요 없습니다. 게시된 후에는 JavaScript를 끈 환경에서도 개별 페이지와 다운로드 링크가 동작합니다.
